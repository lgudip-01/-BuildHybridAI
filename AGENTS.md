# Clause Guard standing constraints

## Strict zero-cost policy

The user never authorizes paid services or monetary charges. This overrides older
roadmap, handoff, publishing and deployment suggestions.

- Never enter, request, save or submit payment information.
- Never create/link billing accounts, upgrade plans, start trials, enable
  auto-renewal, or sign up for paid services.
- Never enable pay-as-you-go services or billable overages, including offers with
  free tiers/credits. Budget alerts are not spending caps.
- Use only verified no-cost services requiring no payment method or billing
  account and incapable of automatically charging money. At quota limits, stop
  or disable the feature; do not upgrade.
- Verify current pricing and actual project/account billing state before cloud
  API activation, deployment, inference, plugin use or subscriptions. If cost is
  uncertain, do not activate/use it; report the blocker and find a no-cost path.
- Broad autonomy or deployment instructions do not authorize payment. Only an
  explicit change to this policy can authorize a paid option.

## Working practices

Read PROJECT_EXECUTION.md and current source before continuing. Preserve existing
local changes and environment configuration. Before each step publish its
checklist and uncertainties, and do not advance until required checks pass or
the user explicitly changes a requirement.

Work autonomously where authorized. Every human-action request must explain why
it is needed, what it changes and what it unblocks. Legal agreements require
informed user review/confirmation; accepting terms is not a zero-cost guarantee.

Keep raw contract text local, require genuine runtime approval for masked cloud
requests, preserve validation and actual inference-source reporting. No paid
inference or provider activation is authorized by previous test evidence.
